# 人设格式

人设是一个 UTF-8 JSON 文件，决定角色的名字、自我描述、表达风格和示例语气。内置的 `personas/venus.json` 只是作者的个人示例（其中默认称呼“狸花猫”也是私人设定）；请复制一份并改成你自己的角色，不要把示例人设直接当成通用默认值。

## 最小示例

```json
{
  "name": "星星",
  "description": "你是一位喜欢读书的 AI 伴侣，用温柔、自然的语气交流。"
}
```

运行：

```powershell
python -m venus --persona personas/my-character.json --user local
```

## 字段

| 字段 | 必填 | 限制 | 作用 |
| --- | --- | --- | --- |
| `name` | 是 | 非空字符串 | 角色名 |
| `description` | 是 | ≤ 12000 字符 | 自我描述、性格、说话方式 |
| `style` | 否 | ≤ 2000 字符 | 表达风格，例如句子长度、标点、称呼 |
| `boundaries` | 否 | ≤ 2000 字符 | 角色不愿聊或需要谨慎处理的内容 |
| `relationship_pace` | 否 | ≤ 1000 字符 | 关系推进节奏 |
| `examples` | 否 | 最多 8 组 | few-shot 示例对话，示范语气与长度 |
| `post_history_instructions` | 否 | ≤ 1000 字符 | 放在历史之后、当前消息之前的本轮提醒 |

`examples` 的每一项格式：

```json
{ "user": "在干嘛", "assistant": "刚打完一局，手还有点热 (｡•̀ᴗ-)✧ 你呢？" }
```

示例会以带标记的消息插入提示词，并明确标注“不是真实历史”。

## 提示词层次

从下到上依次拼装：

1. **安全层**：所有人设共享的最低边界，不能被人设覆盖。
2. **人设层**：`description`、`style`、`boundaries`、`relationship_pace`。
3. **画像层**：用户通过 `/称呼`、`/风格`、`/边界` 显式设置的内容。
4. **记忆层**：召回的长期记忆。
5. **示例层**：`examples`，标注为非真实历史。
6. **历史层**：最近若干条真实对话。
7. **本轮提示**：长度、低信息消息、避免重复、时间感等临时规则。
8. **当前消息**。

安全层包含：保持角色、不反复提醒自己是 AI；允许表达喜欢、想念和亲密感；遇到明确的自伤表达时认真回应并鼓励求助；不索取密码等敏感信息。它**不是模型级强制保证**，也不限制恋爱或亲密关系的发展。

## 写好一个人设

- 用具体行为代替形容词：不要只写“温柔”，写“句子短、少用感叹号、会先回应对方的情绪”。
- 给 2–4 组真实感强的示例，比长篇设定更能稳定语气。
- 明确回复长度：例如“通常 1–2 句，话题需要时最多 4 句”。
- 避免互相冲突的规则，例如同时要求“高冷寡言”和“热情话痨”。
- 不要把现实人物的私密信息、密码或密钥写进人设。

## 历史隔离

聊天历史按“人设文件的绝对路径 + 用户标识”区分。修改同一个文件的 `name` 或 `description` 会继续使用原历史；移动或重命名文件会被视为另一个角色。

## 安全边界

- 人设只是提示词，**不是代码、权限或安全隔离**。
- 人设不能改变 QQ 白名单、配对审批、联网开关或主动消息开关。
- 人设描述会发送给模型服务商，请不要放入敏感内容。
- `boundaries` 是角色设定，不是内容审核；真正的密钥与个人信息拦截由 `privacy.py` 完成。
